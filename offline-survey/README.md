# 离线答卷回传与冲突裁决系统

两台本地设备可断网编辑同一份答卷，答卷与附件分开发送、附件允许晚到；接收工作台先理清
修订关系，再判断完整性，自动裁决字段级合并、保留整份分支并把裁决依据展示在页面上。
**纯 Python 标准库 + 原生前端实现，零第三方依赖，全部数据虚构。**

## 运行

```bash
cd offline-survey
python3 -I run.py 8000        # 或自定义端口
```

- 设备 A：http://127.0.0.1:8000/device.html?device=A
- 设备 B：http://127.0.0.1:8000/device.html?device=B
- 接收工作台：http://127.0.0.1:8000/workbench.html

测试（24 个用例，覆盖全部裁决规则）：

```bash
python3 -I tests/test_engine.py
```

数据落在 `data/`（SQLite 元数据 + `blobs/` 内容寻址附件），可随时在工作台点"重置演示数据"。

## 架构

```
device.html (A/B)                 workbench.html
   localStorage 本地库               冲突裁决 / 收据 / 队列 / 发布门禁
   outbox 断网队列                         │
        │  JSON 信封（delta 字段 + 基准 rev/指纹）      │
        └──────────────► server/app.py (http.server)  ◄┘
                                   │
                  engine.py  接收存证 → FIFO 队列 → 3-way 合并/附件/撤回
                                   │
                  store.py  SQLite（元数据）+ blob 磁盘（SHA-256 内容寻址）
```

## 两阶段接收（收据 ≠ 合并 ≠ 发布）

1. **接收确认**：任何回传先把原始报文写入 `raw_submission` 并立即开收据。收据只代表
   "原始回传可靠保存"——重复回传标 `duplicate`、指纹不符标 `fingerprint_mismatch`、
   结构不合法标 `invalid_json`，都照样存证。
2. **入队处理**：操作进 `op_queue`，按 `seq` 严格 FIFO 处理，结果回写队列；
   进程重启后自动重放仍 `pending` 的任务。
3. **发布**：单独门禁，受附件齐套、未决冲突、撤回状态共同约束，与收据完全解耦。

## 裁决规则

### 字段：3-way 合并（base / head / incoming）

设备只回传**变化字段（delta）**，并带自己的基准 `rev` 与基准指纹。服务端按通过核验的
指纹反查设备真实基准快照（不盲信自报 rev），逐字段判定：

| 情形 | 判定 | 处理 |
|---|---|---|
| 回传值 == base | 设备没改 | 不动 |
| head == base，仅设备改了 | fast-forward | 自动合并 |
| 两边改成同一个值 | converged | 自动合并（仍落修订） |
| 两边改成不同值 | **字段冲突** | 保留服务端值（旧答卷不盖新修改），登记冲突，人工裁定 |

### 指纹不符 → 保留整份分支

设备基准指纹与服务端记录不一致（本地基准被篡改/损坏）时，**不做任何自动合并**，
整份回传原样存入 `branch` 表，登记 `fingerprint` 冲突。人工可选择"应用整份分支"
（整体覆盖为一个新修订）或"丢弃分支"。字段级自动合并与整份分支保留由此明确分工：
指纹可信才走字段级 3-way，指纹不可信只能整份留痕。

### 附件：分开回传、晚到、防挂错

- 附件二进制按 SHA-256 内容寻址落盘，与答卷修订完全独立，可任意晚到。
- **同 ID 同内容**重传 → 幂等；**同 ID 不同内容** → 版本冲突，双版本都保留不覆盖。
- **不同 ID 同名文件挂到同一槽位** → 同名附件冲突，两份暂存，人工确认归属，防止挂错。
- **删除**是软删除（tombstone，blob 保留可恢复）；若该附件存在未决版本冲突，
  删除本身也登记冲突，不能静默吞掉新版本。

### 撤回参与冲突判断、FIFO 不可越序

撤回把答卷置为 `withdrawn` 并登记撤回事件。**撤回之后入队的编辑/附件/删除任务一律
`blocked`**——旧合并任务不能越过更新的撤回去覆盖。人工可解除撤回恢复编辑，或维持终结。

### 发布门禁

以下任一存在即拒绝发布，并在页面列出全部 blocker：答卷已撤回、存在未决冲突、
必交附件槽位不齐套。

## 推荐演示路径

1. 两台设备都打开，分别取消"网络在线"模拟断网。
2. 设备 A 改「客户名称」，设备 B 改「现场备注」（不同字段）；恢复网络 → 自动合并。
3. 两台设备同改「客户名称」为不同值 → 工作台出现字段冲突，查看三方值与裁决依据后人工裁定。
4. 设备 A 点"制造指纹不符"后提交 → 工作台出现整份分支，选择应用或丢弃。
5. 两台设备传同名附件 / 对同一附件传不同内容 → 观察同名冲突与版本冲突。
6. outbox 里点"重复回传" → 收据显示 `duplicate`，不重复生效。
7. 设备 A 撤回，设备 B 随后提交 → 队列里该任务 `blocked`；尝试发布被门禁拦截。
8. 工作台解除撤回、裁决全部冲突、补齐两个必交附件 → 状态变 `ready` → 发布成功。

| `server/engine.py` | 指纹、接收存证、FIFO 队列、3-way 合并、附件/撤回/冲突/发布 |

| `static/js/device.js` | 设备端本地库、断网 outbox、delta 与指纹生成 |
| `static/js/workbench.js` | 工作台视图与人工裁决操作 |
| `tests/test_engine.py` | 24 个端到端规则测试 |
